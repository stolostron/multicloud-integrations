# CLAUDE.md

## Quick Reference — Do These First or Waste Hours

### `deploy/crds/` Is NOT for Operator Version Bumps

`deploy/crds/` contains hub-side CRDs (GitOpsCluster, ManagedServiceAccount, etc.) generated by `make manifests`. During operator manifest updates, CRDs go in `gitopsaddon/charts/openshift-gitops-operator/templates/crds/` — that's the embedded chart. Verify before touching `deploy/crds/` — it's almost never needed for operator bumps. Only modify it if `make manifests` or a hub-side CRD change requires it.

### Pull Secret Chain (Non-OCP clusters WILL fail without this)

The `multiclusterhub-operator-pull-secret` on the hub MUST include `registry.redhat.io` in BOTH `multicluster-engine` and `open-cluster-management` namespaces. Without it, ALL non-OCP managed clusters (Kind, EKS) get `ImagePullBackOff` on every Red Hat image. OCP hubs mask this because nodes have `registry.redhat.io` at the node level.

```bash
# Check
kubectl get secret multiclusterhub-operator-pull-secret -n multicluster-engine -o jsonpath='{.data.\.dockerconfigjson}' | base64 -d | python3 -c "import json,sys; print(list(json.load(sys.stdin)['auths'].keys()))"

# Fix: merge OCP global pull-secret into both copies
kubectl get secret pull-secret -n openshift-config -o jsonpath='{.data.\.dockerconfigjson}' | base64 -d > /tmp/ocp-pull.json
# merge auths from /tmp/ocp-pull.json into multiclusterhub-operator-pull-secret in BOTH namespaces
# then delete {cluster}-import secrets to force regeneration
```

### Agent Mode Setup Order (skip a step = broken)

1. Fix pull secret chain (above) — do this BEFORE anything else for non-OCP clusters
2. Install OpenShift GitOps operator on hub (OLM, `openshift-gitops-operator` ns, `ARGOCD_CLUSTER_CONFIG_NAMESPACES=openshift-gitops`, `DISABLE_DEFAULT_ARGOCD_INSTANCE=false`)
3. Wait for ArgoCD server pod Running in `openshift-gitops`
4. Patch ArgoCD CR: `principal.enabled: true`, `destinationBasedMapping: true`, `controller.enabled: true`, `sourceNamespaces: ["*"]` — **hybrid mode**: the app-controller stays enabled and coexists with the principal in the same namespace/instance; it never conflicts because agent-routed cluster secrets carry `skip-reconcile: "true"` (see "Hybrid Mode" below)
5. Create `ManagedClusterSetBinding` for `global` in `openshift-gitops`
6. Patch default AppProject: `destinations: [{name:"*", namespace:"*", server:"*"}]` — **`name:"*"` is critical**, without it principal won't propagate AppProjects
7. Apply addon templates: `kubectl apply -f gitopsaddon/addonTemplates/addonTemplates.yaml`
8. Create Placement (excluding `local-cluster`) + GitOpsCluster with `argoCDAgent.enabled: true, mode: managed` — `local-cluster` must never be in this Placement; it's not an addon-install target (it already has its own ArgoCD instance)
9. Wait for GitOpsCluster `Ready=True` and Policy `Compliant`
10. **Patch Policy with cluster-admin RBAC for app-controller BEFORE creating AppSet** — if apps sync before RBAC exists, ArgoCD exhausts 5 retries and gives up permanently
11. **Grant the hub's own app-controller ServiceAccount (`openshift-gitops-argocd-application-controller`) cluster-admin too** — needed for any Application targeting `local-cluster`/in-cluster to create resources in its destination namespace; the operator's default ClusterRole is read-only outside `openshift-gitops` itself. Do this before creating the AppSet for the same reason as step 10 (5-retry exhaustion).
12. If ApplicationSets should also target `local-cluster` (hybrid mode), create a **separate** Placement that includes `local-cluster` and point the AppSet's `clusterDecisionResource` generator at it — never reuse the addon-install Placement from step 8 for this
13. Create ApplicationSet(s)
14. Verify apps Synced on hub (including any `local-cluster`-targeted app, reconciled directly by the hub's own app-controller) and guestbook pods on spokes

### Kind Cluster Import Order

The import secret has TWO files. Apply CRDs first or the Klusterlet CR fails:
```bash
kubectl -n <cluster> get secret <cluster>-import -o jsonpath='{.data.crds\.yaml}' | base64 -d | kubectl apply -f -
kubectl -n <cluster> get secret <cluster>-import -o jsonpath='{.data.import\.yaml}' | base64 -d | kubectl apply -f -
```
Then install governance addons (`governance-policy-framework` + `config-policy-controller` ManagedClusterAddOns) or Policies will never be enforced.

### Expected Waits (Not Bugs)

- **Principal CrashLoopBackOff**: Normal when GitOpsCluster is created after ArgoCD CR. Secrets (`argocd-agent-ca`, `argocd-agent-principal-tls`, `argocd-agent-resource-proxy-tls`, `argocd-agent-jwt`) are generated by the hub controller on GitOpsCluster reconciliation. The JWT secret is required by the v1.21.0+ principal for token signing. Principal recovers automatically — can take 5+ minutes due to exponential backoff.
- **Policy NonCompliant on Kind**: The addon agent must install the embedded operator first (creates CRDs + `openshift-gitops` namespace). Takes 2-5 minutes. The Policy can't create the ArgoCD CR until the CRD exists.
- **OCP OLM timing**: Catalog resolution + InstallPlan + CSV = 30-120s even when healthy. Use 600s timeouts.

## Repository Overview

Two components from the same image (`quay.io/stolostron/multicloud-integrations`):

1. **gitopscluster** — Hub-side controller in `multicluster-operators-application` deployment. Reconciles `GitOpsCluster` CRs, creates Policies, MCAs, ADCs, AddOnTemplates, cluster secrets, TLS certs, and handles agent version drift healing.

2. **gitopsaddon** — Addon agent on each managed cluster. Installs OpenShift GitOps operator (OLM on OCP, embedded Helm chart on non-OCP), creates ArgoCD CR, manages image pull secrets, patches ServiceAccounts. Deployed by OCM addon framework.

## Agent Mode Setup — Full YAML

```bash
# 1. Configure hub ArgoCD as principal (hybrid mode: controller stays enabled)
kubectl patch argocd openshift-gitops -n openshift-gitops --type=merge -p '{
  "spec": {
    "controller": {"enabled": true},
    "argoCDAgent": {
      "principal": {
        "enabled": true,
        "auth": "mtls:CN=system:open-cluster-management:cluster:([^:]+):addon:gitops-addon:agent:gitops-addon-agent",
        "destinationBasedMapping": true,
        "namespace": {"allowedNamespaces": ["*"]}
      }
    },
    "sourceNamespaces": ["*"]
  }
}'

# 2. Apply addon templates
kubectl apply -f gitopsaddon/addonTemplates/addonTemplates.yaml

# 3. Create ManagedClusterSetBinding
kubectl apply -f - <<'EOF'
apiVersion: cluster.open-cluster-management.io/v1beta2
kind: ManagedClusterSetBinding
metadata:
  name: global
  namespace: openshift-gitops
spec:
  clusterSet: global
EOF

# 4. Patch default AppProject (name:"*" is critical)
kubectl patch appproject default -n openshift-gitops --type=merge -p '{
  "spec": {
    "destinations": [{"name":"*","namespace":"*","server":"*"}],
    "clusterResourceWhitelist": [{"group":"*","kind":"*"}],
    "sourceNamespaces": ["*"],
    "sourceRepos": ["*"]
  }
}'

# 5. Create Placement + GitOpsCluster
kubectl apply -f - <<'EOF'
apiVersion: cluster.open-cluster-management.io/v1beta1
kind: Placement
metadata:
  name: agent-placement
  namespace: openshift-gitops
spec:
  clusterSets: [global]
  predicates:
  - requiredClusterSelector:
      labelSelector:
        matchExpressions:
        - key: name
          operator: NotIn
          values: [local-cluster]
---
apiVersion: apps.open-cluster-management.io/v1beta1
kind: GitOpsCluster
metadata:
  name: mc-gitops-agent
  namespace: openshift-gitops
spec:
  argoServer:
    cluster: local-cluster
    argoNamespace: openshift-gitops
  placementRef:
    kind: Placement
    apiVersion: cluster.open-cluster-management.io/v1beta1
    name: agent-placement
  gitopsAddon:
    enabled: true
    argoCDAgent:
      enabled: true
      mode: managed
EOF

# 6. Wait for Ready + Compliant
kubectl get gitopscluster mc-gitops-agent -n openshift-gitops -w
kubectl get policy mc-gitops-agent-argocd-policy -n openshift-gitops -w

# 7. RBAC Policy patch — DO THIS BEFORE creating AppSet
kubectl patch policy mc-gitops-agent-argocd-policy -n openshift-gitops --type=json -p='[
  {"op":"add","path":"/spec/policy-templates/-","value":{
    "objectDefinition":{
      "apiVersion":"policy.open-cluster-management.io/v1",
      "kind":"ConfigurationPolicy",
      "metadata":{"name":"mc-gitops-agent-argocd-policy-rbac"},
      "spec":{
        "remediationAction":"enforce","severity":"medium",
        "object-templates":[{
          "complianceType":"musthave",
          "objectDefinition":{
            "apiVersion":"rbac.authorization.k8s.io/v1",
            "kind":"ClusterRoleBinding",
            "metadata":{"name":"acm-openshift-gitops-cluster-admin"},
            "roleRef":{"apiGroup":"rbac.authorization.k8s.io","kind":"ClusterRole","name":"cluster-admin"},
            "subjects":[{"kind":"ServiceAccount","name":"acm-openshift-gitops-argocd-application-controller","namespace":"openshift-gitops"}]
          }
        }]
      }
    }
  }}
]'

# 8. Grant the hub's own app-controller RBAC too (needed for local-cluster/in-cluster targets) —
# DO THIS BEFORE creating any AppSet that targets local-cluster, same 5-retry-exhaustion reason.
kubectl create clusterrolebinding openshift-gitops-appcontroller-cluster-admin \
  --clusterrole=cluster-admin \
  --serviceaccount=openshift-gitops:openshift-gitops-argocd-application-controller

# 9. (Hybrid mode only) Create a SEPARATE Placement that includes local-cluster, used only by
# ApplicationSets that need to target it. Never add local-cluster to "agent-placement" above.
kubectl apply -f - <<'EOF'
apiVersion: cluster.open-cluster-management.io/v1beta1
kind: Placement
metadata:
  name: agent-placement-appset
  namespace: openshift-gitops
spec:
  clusterSets: [global]
  predicates:
  - requiredClusterSelector:
      labelSelector:
        matchExpressions:
        - key: name
          operator: In
          values: [local-cluster]   # plus every managed cluster name you want the AppSet to target
EOF

# 10. Create ApplicationSet (AFTER RBAC is in place). Point at "agent-placement-appset" if it
# should also generate an Application for local-cluster; point at "agent-placement" if it should
# stay agent-spokes-only.
kubectl apply -f - <<'EOF'
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: guestbook-appset
  namespace: openshift-gitops
spec:
  generators:
  - clusterDecisionResource:
      configMapRef: acm-placement
      labelSelector:
        matchLabels:
          cluster.open-cluster-management.io/placement: agent-placement-appset
      requeueAfterSeconds: 30
  template:
    metadata:
      name: '{{name}}-guestbook'
      namespace: openshift-gitops
    spec:
      project: default
      source:
        repoURL: https://github.com/argoproj/argocd-example-apps
        targetRevision: HEAD
        path: guestbook
      destination:
        name: '{{name}}'
        namespace: guestbook
      syncPolicy:
        automated: {prune: true, selfHeal: true}
        syncOptions: [CreateNamespace=true]
EOF
```

## Cleanup (Manual Deletion Order)

GitOpsCluster deletion is a no-op (no finalizer). You must delete resources in this order:
1. Delete ApplicationSet (removes ArgoCD apps)
2. Delete GitOpsCluster (stops controller from re-creating MCAs)
3. Delete Policy + PlacementBinding (stops ArgoCD CR enforcement on spokes)
4. Delete MCAs for each managed cluster (triggers pre-delete cleanup Job)
5. Wait for MCAs to fully delete (2-5 minutes)
6. Delete Placement and remaining resources
7. Optionally delete orphaned ADCs and PlacementDecisions

**Key constraints**: GitOpsCluster BEFORE MCAs. Policy BEFORE MCAs. ADC/AddOnTemplate must still exist when MCAs are deleted.

## Troubleshooting

### Apps Stuck at OutOfSync/Missing After RBAC Fix
ArgoCD auto-sync won't retry a revision that failed 5 times. Fix: delete Application copies on spoke clusters (strip finalizers first). Agent re-dispatches fresh copies.

### Image Pull Issues on Non-OCP Clusters
Almost always the MCH pull-secret chain. Check: `kubectl get secret open-cluster-management-image-pull-credentials -n openshift-gitops-operator` on the spoke, decode it, verify `registry.redhat.io` is present. See "Pull Secret Chain" at top.

### Principal CrashLoopBackOff
Missing secrets. Create a GitOpsCluster with `argoCDAgent.enabled: true` — the hub controller generates `argocd-agent-ca`, `argocd-agent-principal-tls`, `argocd-agent-resource-proxy-tls`, and `argocd-agent-jwt`. Principal auto-recovers.

### Policy Not Compliant
Check replicated policy: `kubectl get policy -n <cluster-name>`. Common causes: `openshift-gitops` namespace doesn't exist yet (addon still installing operator), ArgoCD CRD not registered yet (operator starting up).

### Hub Controller UID Mismatch
`StorageError: invalid object, UID mismatch` after rapid delete/recreate. Fix:
```bash
kubectl delete lease multicloud-operators-gitopscluster-leader.open-cluster-management.io -n kube-system --ignore-not-found
kubectl -n ocm rollout restart deployment/multicluster-operators-application
```

### ArgoCD UI Live Manifest "Resource not found"
1. **DBM mismatch**: Principal has `destinationBasedMapping: true` but agent doesn't. Fix: add `spec.argoCDAgent.agent.client.destinationBasedMapping: true` to agent ArgoCD CR in Policy.
2. **Agent SA missing view ClusterRole**: `kubectl create clusterrolebinding acm-openshift-gitops-argocd-agent-cluster-reader --clusterrole=view --serviceaccount=openshift-gitops:acm-openshift-gitops-agent-agent` on spoke.

### Agent Not Connecting
1. Check principal pod: `kubectl get pods -n openshift-gitops -l app.kubernetes.io/component=principal`
2. Check principal logs: `kubectl logs -n openshift-gitops -l app.kubernetes.io/component=principal --tail=50`
3. Check agent logs on spoke: `kubectl logs -n openshift-gitops -l app.kubernetes.io/part-of=argocd-agent --tail=50`

## Architecture

### Hub Controller ↔ Addon Agent

The **gitopscluster controller** (hub) creates: `AddOnDeploymentConfig` (env vars per cluster), `ManagedClusterAddOn` (triggers addon deployment), `AddOnTemplate` (agent manifests), ArgoCD `Policy` (ArgoCD CR enforcement), `PlacementBinding`, cluster secrets (with `agentName` for agent routing).

The **gitopsaddon agent** (spoke) detects cluster type (OCP/non-OCP/hub), installs the GitOps operator, waits for Policy-deployed ArgoCD CR, patches ServiceAccounts with pull secrets (non-OCP only).

### OCP vs Non-OCP Operator Version Gap (Critical)

OCP and non-OCP managed clusters run **different operator versions**:

- **OCP**: gitopsaddon creates an OLM Subscription (`latest` channel, `redhat-operators` catalog). OLM resolves to whatever version is current in the catalog. All component images (operator, ArgoCD, redis, dex) are determined by the OLM CSV. The hub controller has zero control over these. When Red Hat publishes a new version, OCP clusters auto-upgrade.

- **Kind/EKS (non-OCP)**: gitopsaddon deploys the **embedded Helm chart** (`gitopsaddon/charts/openshift-gitops-operator/`). The version is in `Chart.yaml`. All component images are hardcoded SHA digests in `pkg/utils/config.go` `DefaultOperatorImages`. These never change until someone runs the Manifest Update Procedure.

- **Agent image is the exception**: On both OCP and Kind, the argocd-agent image comes from the hub controller's drift heal — it reads the principal pod's image and writes it into the Policy. So the agent image is always consistent with the hub principal regardless of spoke operator version.

- **The version gap means**: the embedded operator on Kind/EKS may lack features, CRD fields, or RBAC rules added in newer OCP versions. When bumping, update: `Chart.yaml` version, CRDs (extract from hub), ClusterRole rules (from CSV), image SHAs in `config.go`. See Manifest Update Procedure.

- **Manifest update lessons**: (1) ClusterRole rules extracted from CSV contain `*` wildcards that MUST be quoted as `"*"` in YAML — unquoted `*` is a YAML alias and causes silent parse failures (the ClusterRole is never created, operator crashes with informer cache sync timeouts). (2) Route and Monitoring CRD stubs are NOT needed — the operator has proper API discovery (`argoutil.VerifyAPI()` / `InspectCluster()`) that gracefully skips Route and Monitoring watches when the APIs don't exist on non-OCP. (3) Run `test-cycle.sh` for at least 2 cycles to catch inter-cycle state issues. (4) **Do NOT modify anything from the source of truth** — if the CSV has duplicate rules, empty apiGroups, OLM labels on CRDs, or other quirks, keep them in the chart exactly as extracted. The chart must match the source of truth (hub cluster, orb bundle, upstream repos). Fixing upstream issues in the chart causes it to go out of sync and makes future verification impossible. The same applies to CRD metadata labels — if the hub CRDs have `operators.coreos.com` labels, keep them. The gitopsaddon label (`apps.open-cluster-management.io/gitopsaddon: "true"`) is added at deploy time by `templateAndApplyChart`, not in the chart YAML itself.

### Hybrid Mode (hub app-controller + argocd-agent principal, same instance)

The hub runs a **single** ArgoCD instance in `openshift-gitops` that hosts both the argocd-agent
principal (dispatching to managed clusters) and its own application controller (`controller.enabled:
true`) reconciling anything targeting `local-cluster`/in-cluster directly. There is no separate
ArgoCD instance or namespace for the hub — that legacy design (a dedicated `local-cluster`
namespace with its own agent-connected ArgoCD instance) has been removed.

- **Isolation mechanism**: every agent-routed cluster secret (`cluster-<name>` for real spokes)
  carries `argocd.argoproj.io/skip-reconcile: "true"`, so the hub's app-controller ignores anything
  dispatched to an agent and lets the principal own it exclusively. `local-cluster`'s own cluster
  secret (`cluster-local-cluster`, created by `ensureLocalClusterSecret` in
  `argocd_agent_clusters.go`) carries **no** skip-reconcile and **no** agent-name label — it's a
  plain cluster secret pointing at `https://kubernetes.default.svc`, so the hub app-controller
  reconciles it like any other in-cluster ArgoCD destination.
- **`local-cluster` is never an addon-install target**: it already has GitOps operator + ArgoCD
  installed independently (a prerequisite, not addon-managed). The `GitOpsCluster`'s own
  `placementRef` must always exclude `local-cluster` — the addon-install loop
  (`CreateAddOnDeploymentConfig`/`EnsureManagedClusterAddon`) and the ArgoCD-CR-enforcing Policy
  both skip/must never select it (`IsLocalCluster` guards this in
  `gitopscluster_controller.go`/`argocd_agent_clusters.go`; a warning is logged if the Placement
  ever resolves to include it, since the Policy would otherwise deploy a second, conflicting
  ArgoCD CR into `openshift-gitops`).
- **ApplicationSets targeting `local-cluster`**: use a Placement **separate** from the
  GitOpsCluster's own `placementRef` — this one is free to include `local-cluster` alongside real
  managed clusters. The generated Application resolves `destination: {name: 'local-cluster'}`
  against the plain `cluster-local-cluster` secret and gets created in `openshift-gitops`,
  reconciled by the hub's app-controller.
- **RBAC**: the operator's default ClusterRole for the app-controller is read-only outside
  `openshift-gitops` itself. Any Application targeting `local-cluster` needs the hub
  app-controller's own ServiceAccount (`openshift-gitops-argocd-application-controller`) granted
  elevated RBAC (e.g. `cluster-admin`, matching the same pattern already used for spoke
  app-controllers) in whatever destination namespaces those apps create — do this **before**
  creating the AppSet, or the first sync attempt exhausts ArgoCD's 5-retry budget and self-heal
  won't retry a revision that already failed that many times.

## Key Features (Deep Reference)

### Agent Version Drift Heal
Controller watches the principal Deployment (`app.kubernetes.io/component=principal`) for image changes. When the image changes (operator upgrade), it patches the ArgoCD Policy's `argoCDAgent.agent.image` to match. Only the `acm-openshift-gitops` template is patched. `findContainerImage(containers, deploymentName)` checks: (1) container named `"principal"`, (2) container matching deployment name, (3) `containers[0]`.

### Cert Rotation & Autorefresh
`argocd-agent-client-tls` has 24-hour validity. OCM `ClientCertController` rotates at ~80% lifetime. `SecretReconciler` propagates via: source watch (immediate), target deletion watch (instant re-copy), periodic requeue (5 min safety net). On actual cert data change, rolling-restarts all agent Deployments (`app.kubernetes.io/part-of=argocd-agent`).

### Resource Proxy TLS SAN
`argocd-agent-resource-proxy-tls` cert must include the resource-proxy service DNS name. `getResourceProxyHostNames` calls `FindArgoCDAgentResourceProxyService` directly. `deleteSecretIfSANsDrifted` detects missing SANs and deletes the secret for re-issuance. Workaround: `kubectl delete secret argocd-agent-resource-proxy-tls -n openshift-gitops`.

### Cluster Secret Server URL
Preferred: resource proxy URL `https://...-resource-proxy.<ns>.svc:9090?agentName=<cluster>`. Fallback: NodePort/LoadBalancer address. Routing by `argocd-agent.argoproj-labs.io/agent-name` label.

### Skip-Reconcile Annotation on Agent Cluster Secrets
Agent cluster secrets are stamped with `argocd.argoproj.io/skip-reconcile: "true"`. This tells the ArgoCD application controller on the hub to skip reconciliation for applications targeting that cluster — the agent handles reconciliation instead. Required for hybrid mode where a traditional app-controller coexists with the argocd-agent principal on the same hub. Without it, both the hub app-controller and the agent try to reconcile the same apps, causing conflicts. Set automatically by `CreateArgoCDAgentClusters` — no manual action needed.

### Non-Agent → Agent Mode Transition
Creating agent mode after non-agent creates duplicate cluster names. `CreateArgoCDAgentClusters` calls `deleteBlankClusterSecretsForCluster` to remove old blank pull-model secrets.

### OLM Subscription Details
Always in `openshift-gitops-operator` ns. OperatorGroup must be AllNamespaces (not OwnNamespace). `patchArgoCDCRDConversionWebhookIfNotReady` patches CRD conversion to `None` before subscription. `recoverFromFailedWebhookInstallPlan` handles failed InstallPlans from webhook timeout.

### Addon RBAC
`gitops-addon` ClusterRole (fine-grained, not cluster-admin). Defined in both `addonTemplates.yaml` (static) and `addon_template_management.go` (dynamic). Separate `gitops-addon-cleanup` ClusterRole annotated `addon-pre-delete` for cleanup Job RBAC. Includes `escalate`/`bind` for operator leader-election Role.

### Cleanup Rules
**NEVER list-and-delete blindly.** Only delete: (1) gitopsaddon-labeled ArgoCD CRs (waits for operator finalizer), (2) OLM Subscription/CSV on OCP, (3) gitopsaddon-labeled operator resources on embedded. ArgoCD workloads are the operator's responsibility. Never force-strip ArgoCD CR finalizer. On OCP, skip `deleteOperatorResources` — OLM handles it. `templateAndApplyChart` labels all resources with `apps.open-cluster-management.io/gitopsaddon: "true"`.

### Custom ArgoCD Namespace
`spec.argoServer.argoNamespace` overrides the namespace. `GetEffectiveArgoNamespace()` must be used for all operations (cert gen, CA propagation, service discovery).

### Image Pull Secret Chain (Non-OCP)
Hub `multiclusterhub-operator-pull-secret` (in `multicluster-engine` + `open-cluster-management`) → `managedcluster-import-controller` bakes into `{cluster}-import` secret → klusterlet copies as `open-cluster-management-image-pull-credentials` → addon copies to ArgoCD namespaces → `patchServiceAccountsWithImagePullSecrets` patches all SAs. `installViaEmbeddedManifests` patches operator SA immediately after chart apply, deletes ImagePullBackOff pods.

## Manifest Update Procedure (OpenShift GitOps Operator)

Hub cluster is the source of truth. Upstream repos ([redhat-developer/gitops-operator](https://github.com/redhat-developer/gitops-operator), [argoproj-labs/argocd-operator](https://github.com/argoproj-labs/argocd-operator)) are for cross-referencing — local reference copies of these repos are in the repo root. Use `orb` for independent bundle verification.

### Verification direction: SOURCE FIRST, then chart

**Always start from the source of truth (hub cluster / orb bundle / upstream repo), enumerate everything it has, then check whether the chart matches.** Never start from the chart and ask "does this look right" — that misses resources that should exist but don't, and resources that should be deleted but still exist. The source tells you what SHOULD be there; the chart is what you're validating.

### What to update (complete checklist)

CRDs, ClusterRole, images, and Deployment env vars are obvious. But also check: leader-election Role rules, ConfigMap content, ServiceAccount changes, new/removed Services, new env vars in the Deployment template, new ports, new volumes, changed args/probes. The OLM bundle restructures RBAC (hashes names, combines roles) — the chart keeps them separate with readable names. Don't blindly copy OLM structure.

1. **Verify target version**: `kubectl get csv -n openshift-gitops-operator | grep openshift-gitops`
2. **Extract CRDs**: `kubectl get crd <name> -o yaml`, strip runtime metadata (`uid`, `resourceVersion`, `creationTimestamp`, `generation`, `managedFields`, OLM annotations/labels, `status`), disable conversion webhooks (`strategy: None`, remove `webhook` block), escape Go templates (`{{ }}` → `{{ "{{" }}`). Place in `gitopsaddon/charts/openshift-gitops-operator/templates/crds/` ONLY. `deploy/crds/` is unrelated.
3. **Update manager ClusterRole**: Extract from CSV `spec.install.spec.clusterPermissions[0].rules`. **Quote all `*` wildcards as `"*"`** — unquoted `*` is a YAML alias. Validate: `python3 -c "import yaml; yaml.safe_load(open('file'))"`.
4. **Update leader-election Role**: Extract from CSV `spec.install.spec.permissions[0].rules`. Compare with `templates/openshift-gitops-operator-leader-election-role.role.yaml`.
5. **Update image SHAs**: Extract from CSV env vars (non-`RELATED_IMAGE_` ones) and container image spec. Update `pkg/utils/config.go` `DefaultOperatorImages`. Also check for new/removed env var names.
6. **Update Deployment template**: Compare CSV deployment spec with `templates/openshift-gitops-operator-controller-manager.deployment.yaml`. Check for: new env vars, changed args, new ports, changed probes, new volumes/mounts. The chart should match the source except for these intentional differences:
   - `ENABLE_CONVERSION_WEBHOOK=false` (source=`true`) — no OLM conversion webhook on non-OCP
   - `DISABLE_DEFAULT_ARGOCD_INSTANCE=true` (source=`false` on OCP) — embedded chart disables default instance
   - `--metrics-bind-address=127.0.0.1:8080` (source=`:8443`) — kept as-is to avoid behavior change (metrics go from localhost-only to externally accessible); changing would also require updating the ConfigMap
   - `seccompProfile.type: RuntimeDefault` (source doesn't have it) — extra security hardening on non-OCP, kept for defense-in-depth
   - `ARGOCD_CLUSTER_CONFIG_NAMESPACES="*"` (source=`openshift-gitops`) — chart uses wildcard so all namespaces get cluster-scoped RBAC
7. **Bump Chart.yaml version**
8. **Check new/removed resources**: Compare old and new CSV for new ServiceAccounts, Services, ConfigMaps, Roles. The OLM bundle has monitoring resources (ServiceMonitor, prometheus Role) that are NOT needed in the embedded chart.
9. **Cross-reference with `orb`**: Extract the bundle independently and verify CRD count, image SHAs, and ClusterRole rules match (see orb section below).
10. **Cross-reference with source repos**: Check the local reference copies of [gitops-operator](https://github.com/redhat-developer/gitops-operator) and [argocd-operator](https://github.com/argoproj-labs/argocd-operator) for API discovery behavior changes (e.g., how Route/Monitoring APIs are handled on non-OCP).
11. **Build and test**: `make build && make test`, then run `test-cycle.sh` for at least 10 cycles with both OCP and Kind clusters.

### orb Tool (Verification)
`go install github.com/joelanford/orb/cmd/orb@latest`. Requires `pkg-config` and `libgpgme-dev` system packages. Requires `DOCKER_CONFIG` with `registry.redhat.io` auth. Extract bundle: `DOCKER_CONFIG=/tmp/orb-auth orb bundle convert plain docker://registry.redhat.io/openshift-gitops-1/gitops-operator-bundle:vX.Y.Z dir:/tmp/orb-output -n openshift-gitops-operator`. The output `manifests.yaml` contains all CRDs and non-CRD resources. Compare CRD names, image SHAs, and ClusterRole rules against the chart. The OLM bundle uses hashed ClusterRole names and combines RBAC differently — compare rule CONTENT, not names.

## CI Pipeline

## E2E Testing Gotchas

- **CI timing**: ArgoCD sync is slow on CI runners. Don't assert `Synced` with tight timeouts.
- **`test-local-*` vs `test-e2e-*`**: Local creates fresh Kind clusters. Always use local to mirror CI.
- **Principal container naming**: Red Hat operator: `"principal"`. Upstream: deployment name. `findContainerImage` handles both.
- **Helm `{{` in CRDs**: Escape as `{{ "{{" }}`. Check `imageupdaters` CRD.
- **Kubeconfig contamination**: Unset `KUBECONFIG` before `make test-local-e2e-*` or Kind writes into hub kubeconfig.
- **`appProjectYAML` must include `name: '*'`**: Without it, principal skips AppProject propagation → agents have no AppProject → apps stuck at `sync=Unknown`.
- **`sync=Unknown health=Healthy`**: Principal never dispatched. Check: (1) app on spoke? (2) AppProject exists? (3) agent pod logs for gRPC errors.
- **argocd-agent-resource-proxy-tls bootstrap**: Principal FATAL if missing. Early cert generation block in controller generates before `VerifyArgocdNamespace`.
- **Principal TLS NodePort SAN**: `getPrincipalHostNames` adds node IPs when no LoadBalancer ingress exists.
- **UID mismatch after cleanup**: Rapid delete/recreate causes stale informer cache. `isObjectGoneError()` aborts reconcile. Fix: restart controller + delete lease.
- **OperatorGroup must be AllNamespaces**: `OwnNamespace` causes CSV failure.
- **CSR accumulation**: Rapid deploy/delete cycles exhaust CSR quota. Fix: `kubectl get csr -o name | grep gitops-addon | xargs kubectl delete`.
- **ACM 2.16→2.17 CRB roleRef immutability**: `deleteStaleClusterRoleBinding()` self-heals at startup.
- **Addon agent race during cleanup**: `scaleDownAddonAgent()` scales to 0 before cleanup Job runs.
- **local-cluster guestbook (hybrid mode)**: local-cluster is never agent-dispatched, so there is no hub-vs-spoke identity conflict to work around. Its Application is verified and finalized normally through the hub's own application controller, same as any other in-cluster ArgoCD destination - see "Deploy/Delete Cycle Testing" below.

## Deploy/Delete Cycle Testing

`gitopsaddon/test-cycle.sh` — automated deploy/verify/delete cycling against **real** clusters
(not the Kind-only `make test-local-e2e-*` targets). This is the primary way to validate hybrid
mode end-to-end: it always includes `local-cluster` in the ApplicationSet target (via a dedicated
`cycle-agent-appset-placement`, kept separate from the addon-install `cycle-agent-placement` which
still excludes `local-cluster`), verifies the `cluster-local-cluster` secret shape and that the
generated app reconciles via the hub's own application controller, and tears everything down with
no manual finalizer stripping anywhere in the script: it deletes the ApplicationSet first (per the
"Cleanup (Manual Deletion Order)" section above), while agents and the hub app-controller are still
connected, and waits for every generated Application — spoke-managed and `local-cluster` alike — to
finalize naturally before touching GitOpsCluster/Policy/MCAs.

```bash
HUB_KUBECONFIG=/path/to/hub \
MANAGED_CLUSTERS="eks-cluster1:/path/to/eks.kc,ocp-cluster-name:/path/to/ocp.kc" \
  bash gitopsaddon/test-cycle.sh 5
```

Optional env vars: `FORCE_CLEAN_FIRST` (true), `WAIT_DEPLOY_SECS` (600), `WAIT_CLEANUP_SECS` (600), `HUB_CONTROLLER_NS` (ocm).

Prerequisite (one-time, per hub): the hub's own ArgoCD app-controller ServiceAccount needs
elevated RBAC to manage the `local-cluster` hybrid app's destination namespace — see "Hybrid Mode"
above. `test-cycle.sh` creates this itself (`ensure_hub_appcontroller_rbac`) so no manual step is
needed for the script specifically, but real (non-test) hybrid-mode setups must do this too.

### Building/pushing images from a Flatpak-sandboxed shell (e.g. this coding agent's Bash tool)

If `docker`/`podman`/`kind`/`go` aren't visible in the shell but ARE installed on the real host,
the shell is likely running inside a Flatpak sandbox layer (check `cat /etc/os-release` — a
`Freedesktop SDK ... (Flatpak runtime)` result confirms it). Escape it with
`flatpak-spawn --host <command>` to run the command on the real host instead — this reaches the
host's actual `podman`, `kind`, and `go` installs, registry credentials, and any existing local
Kind clusters. Plain `kubectl` against real remote clusters typically works fine without the
escape hatch (outbound network is already shared); use `flatpak-spawn --host` for anything that
needs the host's container/VM tooling specifically.

## Known Limitations

1. **Policy is user-owned**: Controller recreates deleted Policies (unless `skip-argocd-policy`), may patch `argoCDAgent.agent.image` during drift heal, but doesn't overwrite other customizations.
2. **Cleanup order matters**: GitOpsCluster → Policy → MCAs (strict order or resources get recreated).
3. **GitOpsCluster deletion is a no-op**: No finalizer, no cascade.
4. **`local-cluster` must stay out of the GitOpsCluster's own `placementRef`**: it's never an
   addon-install target (hybrid mode) — it already has its own ArgoCD instance. A separate
   Placement, used only by ApplicationSets, may include it.
5. **OLM mode OCP only**: Non-OCP uses embedded Helm chart.
6. **RBAC before first app sync**: ArgoCD retry limit (5) means stuck apps if RBAC missing. Delete spoke app copies to recover. This applies to the hub's own app-controller too for any app targeting `local-cluster`.
7. **Non-OCP pull secret chain**: `multiclusterhub-operator-pull-secret` must have `registry.redhat.io` in BOTH namespaces.
8. **OCP OLM timing**: 30-120s. Use 600s timeouts.
9. **DBM must match principal and agent**: Mismatched = "Resource not found" in UI.
10. **Agent SA view ClusterRole**: Not auto-provisioned. Add manually or via Policy.
